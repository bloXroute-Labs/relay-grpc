# AGENTS.md

## What this repo is

`relay-grpc` is the **shared gRPC schema + generated code** that defines how builders
and internal services talk to the bloXroute MEV relay. It is a library/interface
package, not a running service. Its two primary consumers are:

- **`mev-boost-relay`** — the relay itself (see `../mev-boost-relay`).
- **`rproxy`** — the regional relay proxy that fronts and replicates a subset of relay
  functionality (see `../rproxy`).

Go module: `github.com/bloXroute-Labs/relay-grpc` (Go package `relay_grpc`).
Rust crate: `proto` under `rust/proto`.

## Source of truth: `blxr-mev.proto`

`blxr-mev.proto` is the single source of truth. It defines the `Relay` service
(`SubmitBlock`, `GetHeader`, `GetPayload`, `StreamHeader`, `StreamBlock`,
`StreamBuilder`, `RegisterValidator`, `AdjustLatestBlockPayload`, etc.) and all message
types.

**Never hand-edit generated files.** Edit the `.proto`, then regenerate:

```bash
./run_proto.sh
```

Generated artifacts (do not edit directly):
- `blxr-mev.pb.go` — Go messages
- `blxr-mev_grpc.pb.go` — Go gRPC client/server stubs
- `rust/proto/src/blxrmev.rs`, `rust/proto/src/blxrmev.tonic.rs` — Rust (prost + tonic)

`run_proto.sh` requires: `protoc` (v26.1; zips are vendored in-repo), the Go plugins
`protoc-gen-go` / `protoc-gen-go-grpc` on `PATH` (under `$(go env GOPATH)/bin`), and the
Rust plugins `protoc-gen-prost` / `protoc-gen-tonic` (the script `cargo install`s them).

**Known quirks (intentional, do not "fix" casually):**
- The proto has **no `package` declaration** — commented out pending coordination with
  external builders. The Rust generation compensates with `mv`/`sed` steps that rename
  the default `_`/`.tonic.rs` outputs to `blxrmev.*`. Adding a `package` would break
  downstream builders and must be coordinated.
- `option go_package` contains a typo (`bloXoute-Labs`); the real import path is
  `bloXroute-Labs`. Harmless because generation uses `paths=source_relative`.

## Hand-written Go code (lives beside generated code, same package)

These are maintained by hand and must be updated when the schema changes:

- `conn.go` — connection helpers: `NewRelayConnection`, `NewConnection`,
  `ConnectToGRPCService` (auth token, gzip, keepalive).
- `utils.go` — top-level conversions between attestantio versioned types and proto:
  `VersionedRequestToProtoRequest`, `ProtoRequestToVersionedRequest`, byte-array helpers.
- `get_header.go` — small constructors.
- **Per-fork conversion files**: `capella.go`, `deneb.go`, `electra.go`, `fulu.go`.
  Each fork gets its own file with a consistent set of converters
  (`<Fork>RequestToProtoRequest`, `ProtoRequestTo<Fork>Request`, header-submission and
  builder-bid converters, etc.). **When a new Ethereum fork lands, add a new
  `<fork>.go` mirroring the newest existing file** (currently `fulu.go`) rather than
  overloading an existing one. `utils.go` dispatches by `consensusspec` version.

## Subpackages

- `bidadjustment/` — SSZ types and logic for builder bid adjustment (`AdjustBlock`,
  versioned `AdjustmentData` V1/V2/V3). SSZ marshalers here are **generated by
  `sszgen`**, not protoc — regenerate via `./generate_adjustment_data_types.sh` after
  editing `bidadjustment/types.go`.
- `optimisticv3/` — optimistic v3 types (also SSZ-generated).
- `stat/` — endpoint performance stat helpers.

## Build / lint / test

```bash
make lint          # go vet ./... + golangci-lint (timeout 5m)
go build ./...
go test ./...      # tests live in bidadjustment/, optimisticv3/, etc.
```

Rust: `cargo build` inside `rust/proto`.

## Workflow expectations for changes

1. Edit `blxr-mev.proto` (schema) and/or the hand-written Go converters.
2. Regenerate with `./run_proto.sh` (and `./generate_adjustment_data_types.sh` if SSZ
   types changed). Commit generated files together with the source change.
3. Keep Go and Rust in sync — both are generated from the same proto in one script run.
4. Adding/removing/renaming proto fields is a **cross-repo contract change**: it affects
   `mev-boost-relay` and `rproxy` (and external builders). Preserve field numbers; treat
   removals and renumbering as breaking.
5. Run `make lint` before committing.
